# 三维控制的执行器与外部视觉接入

2026-10-30 v3。已在独立开发副本中完成 A1 协议执行器适配、外部 ROS 视觉反馈接入及三维任务节点，沿用 Mark 工作站固定 ROS2 Jazzy 镜像，以两路伪串口和独立位姿发布进程完成整链路验证。旧版本、原实机流程文档和 PPT 保留。

本次完成的是接口实现与离线验证。没有连接电机、真实相机、底盘或其他物理设备，没有运行真实图像的在线 SLAM，也没有获得机械臂实机精度或电源可靠性结论。

## 1. 本次接通的链路

`独立ROS位姿/源状态 → 坐标变换与时效检查 → 三维目标控制 → 四通道索长指令 → 原生A1协议/CRC → 两路PTY → 独立电机板模拟`

位姿发布器、控制节点和测试客户端位于不同进程。电机板模拟器在测试端解释真实 34 字节请求、生成 78 字节反馈并独立计算 CRC。控制节点通过现有 C++/SDK 编解码与原生接收路径获得编码器证据，没有调用测试端的机构真值函数。

控制器只读取经过配对的外部位姿和实际串口回复。模拟机构的非线性前向模型与控制器初始雅可比不同，测试端用自己的物理状态计算最终误差，不用控制器估计结果充当真值。

## 2. 执行器接口

新增 `actuator_io.py`，由调用者显式提供经过验证的文件描述符传输工厂和四路安装标定。接口本身不发现或打开设备路径。

每路标定明确总线、ID、方向、有效卷筒半径、减速比、编码器参考、索长参考、伺服增益及反馈力矩/温度限值。根据编码器测量转换索长，反向生成 A1 位置指令，按配置速度在各小步之间插值。位置、步长和行程限制均在执行前检查，回复须具有正确 ID、模式、CRC、新事务编号和有效接收时间。

全部串口创建、轮询、运动、停止和关闭由 `cartesian-fd-owner` 单个线程拥有。ROS 回调只提交目标、请求取消或读取缓存。启动先以零努力请求读取反馈，不自动展开；显式参考确认后保持实测位置，不将任意启动角度当零位，也不自动归零或回家。

到位后继续维持目标与监测反馈，不能在成功后一轮空闲轮询就卸力。视觉失效或串口异常会停止并锁存。停止回执逐一关联原生事务，无法确认的通道明确保留 `reply_valid=false`。

原生传输发生 CRC、ID 或超时等错误时会隔离相应总线，后续停止请求可能无法真正发出或获得回复。这种情况是“故障已锁存、软件停止未全部确认”，不能写成四电机已经物理停止。实机仍需独立的停止/断电/支撑措施和保持验证。

电机接收新鲜度来自主机实际验证的 RX 时间，A1 回复没有在本轮提供可用的设备采样时间或设备序号。此证据不等于独立测得了电机内部传感采样年龄。反馈力矩也不等于索张力或电源电流。

## 3. 视觉反馈接口

新增 `external_vision.py`，复用已有 `RosPoseBridge` 配对如下两类消息。

| 输入 | 类型 | 必需约定 |
|---|---|---|
| `atarm/camera/pose` | `geometry_msgs/PoseStamped` | 米制位置、有效姿态、原始捕获时间、明确源父坐标系 |
| `atarm/camera/source_status` | `std_msgs/String` | 同一 `stamp_ns`，源 `frame_id`、`tracking_ok`、`metric`、`map_epoch`、`child_frame` |

缺少同时间戳配对时不产生观测。失跟、非米制、错误坐标、地图变化、时间回退、陈旧或未来时间及消息篡改均拒绝。捕获时间保持原值，ROS 发布时间不冒充曝光/采样时间。

源位姿通过配置的 `T_base_source · T_source_camera · T_camera_control` 变换到统一控制点。工具偏置随相机姿态旋转，既有源帧号、捕获时间与地图会话保持不变。变换绑定当前会话，不猜尺度、不自动估计外参、不以临时 TF 替换已确认标定。

启动时若还未接受任何有效帧，DDS 发现阶段补发的历史陈旧样本会被丢弃并计数，等待新鲜成对观测。没有伪造新观测，也没有解除已锁存故障。接受第一帧有效观测后，仍执行原有故障锁存。视觉 150 ms、电机 100 ms 门槛没有放宽。

这层接口可以接收符合契约的真实定位输出；当前验证发布器仍为合成源。相机驱动、真实图像 SLAM、基座锚定外参、跨主机时钟与现场负载时效仍需现场确认。

## 4. ROS 三维任务接口

新节点为 `cartesian_fd_node`，保留旧模拟节点及旧硬件节点文件不变。

| 名称 | 类型 | 含义 |
|---|---|---|
| `atarm/cartesian/target` | `std_msgs/String` | 唯一 ID 的三维位置目标 |
| `atarm/cartesian/ack` | `std_msgs/String` | 目标受理/拒绝，不代表完成 |
| `atarm/cartesian/state` | `std_msgs/String` | 20 Hz 缓存状态、任务、参考系和反馈证据 |
| `atarm/cartesian/confirm_reference` | `std_srvs/Trigger` | 提交一次有时限的参考检查，不归零、不移动回参考点 |
| `atarm/cartesian/cancel` | `std_srvs/Trigger` | 取消当前可取消任务 |

启动状态为 `UNCONFIRMED`。参考确认请求获受理后，须等待多帧稳定视觉窗口及四路实测索长符合显式标定，状态才变成 `READY`。参考确认服务仍依赖操作者对物理参考形态的独立确认；编码器一致性检查不能替代实物检查。

目标受理后依次进入 `ACCEPTED`、`RUNNING` 和最终状态。仅 `SUCCEEDED` 且 `success=true`、`complete=true` 表示最终位置被确认；单个伸缩/弯曲动作不能代替整条任务完成。取消和最终提交按同一任务锁确定先后，进入最终提交阶段后的迟到取消会拒绝，不出现“已接受取消却仍报告成功”。

目标样例如下，仅用于当前合成标定。

```json
{"request_id":"goal_001","position_m":[0.3124208,0.03748,0.1949592],"parent_frame":"control_base","child_frame":"tcp","map_epoch":"validation_map_0"}
```

未确认参考、重复 ID、忙碌目标、NaN 和错误地图目标拒绝。取消/故障后拒绝重试，必须结束当前会话，检查原因与机械参考，再显式建立新会话。本版本不提供一个会自动清故障、重置编码器或继续旧目标的 reset 服务。

每条目标从配置的同一初始雅可比开始；有界在线更新在该目标内部进行，更新历史完整保存，不把上一目标学到的模型静默带入下一目标。

## 5. 实际验证

本地新接口检查 12 项、三维数值控制回归 22 项、原模拟任务接口回归 6 项，共 40 项通过。涉及导入隔离的原测试使用独立 Python 进程，未修改原断言以适应测试污染。接口检查包括初始化失败时清除待处理请求并拒绝后续目标。

最终工作站结果为 `fd05_matrix`，18 类实际 rclpy/DDS、原生 A1 协议和 OS 伪串口用例全部通过。各控制节点和位姿源正常退出，工作线程结束，四通道 I/O 只有规定的所有者线程。

| 场景 | 实际结果 |
|---|---|
| complete，交替协调 | 到位；独立模拟真值误差约 0.222 mm |
| coordinated，同步协调 | 到位；独立模拟真值误差约 0.203 mm |
| cancel | 取消；四路停止回复有效；故障会话不自动重试 |
| tracking_lost | 跟踪丢失后故障，不报完成 |
| frozen_pose | 源帧冻结后因位姿陈旧而故障 |
| map_reset | 地图会话改变后故障 |
| wrong_frame | 错误源坐标系拒绝 |
| delayed_pose | 时间戳回退/过期拒绝；本例先命中时间回放保护 |
| nonmetric | 非米制尺度拒绝 |
| bad_crc | 原生 CRC 校验失败，停止未全部确认，故障锁存 |
| wrong_id | 回复电机编号错误，故障锁存 |
| timeout | 串口超时，故障锁存 |
| motor_error | 电机反馈错误码，故障锁存 |
| stall | 电机不随命令移动，稳定等待超时，不报到位 |
| false_encoder | 编码器回复目标值但独立视觉未移动，判定无进展，不报到位 |
| reference_mismatch | 起始编码器不符合参考，保持 UNCONFIRMED，不发位置伺服运动 |
| hold_fault | 已到位后的保持期间丢失跟踪，仍能检测并转故障 |
| shutdown | 运动中退出，停止/关闭并回收工作线程 |

取消服务请求至首个有效软件停止请求约 0.404 ms，属于本次容器、DDS 与伪串口命令链路测量，不是机械制动时间。亚毫米误差只属于已声明的合成机构，不代表实机精度。

测试容器固定为既有镜像 `ros@sha256:8eed0a4669bbf43ee331878a4c39bd8ebddea8e3312a58b4fae8edb14526b617`，无外网、无物理设备映射、非特权、只读根文件系统与源码，使用普通用户，只写任务专属结果目录。上传清单为 22 个文件、约 81 KB 压缩包，不含原录包、指南中的凭据或用户附件。容器已退出并删除，工作站系统与镜像未安装或改动。

## 6. 如何复现与接入

开发副本为 `01_Source/development/atarm_controller_cartesian_fd_20261030_v3`；本地编排程序为 `03_Experiments/cartesian_fd_20261030_v3/remote.py`。在现有授权 SSH 环境下执行以下命令会在 Mark 工作站启动无硬件的隔离测试；每次必须使用新的结果名。

```powershell
& 'C:/Users/43767/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe' -B 'D:/Research/Mark_Agricultural_Robot/03_Experiments/cartesian_fd_20261030_v3/remote.py' run --name fd_review_01 --case all
```

测试程序自动创建两路 PTY，分别把已打开描述符交给节点的 `--active-fd` 与 `--deploy-fd`，使用 `--offline-pty`、`--session-config` 和 `--audit` 显式运行模块。直接按设备路径或省略参数启动会拒绝；不应把任意整数当描述符，也不应把合成配置抄给实物。

真实集成入口是 `FdCartesianNode(session_path, transport_factory)` 与 `FdActuatorIO`。调用者负责供应经白名单和现场配置验证的传输工厂；接口不暗中打开设备。当前 CLI 只允许 PTY，当前原生库也保持 physical UART 默认关闭。真实部署时仍需单独落实设备身份、波特率/串口配置、经授权的描述符交接与物理 UART 构建版本，这些均未在本轮启用。

`setup.py` 增加了 `cartesian_fd` 入口，但本轮使用模块方式启动，没有运行 colcon 安装/打包验证。

## 7. 仍须上机确认

1. 按 Mark 的先后顺序，先确认新电源、展开/保持/收回和小幅弯曲的可靠性，测电压、电流与实际停止保持。
2. 核对四电机总线、ID、方向、卷筒有效半径、参考编码器与索长，以及安全增益、行程、速度、力矩/温度限值。现有配置全部是合成假设。
3. 检验展开时是否需要三路弯曲索共同收放以维持张力；当前 4×3 映射没有主动共同张力控制，不能把电机力矩当索张力。
4. 在真实定位节点上确认米制尺度、基座/相机/控制点外参、源捕获时间和时钟关系，以及运动全程 150 ms 视觉时效。
5. 用实测数据建立初始三维雅可比与有效局部范围，再执行混合三维目标，使用独立参照确认实际误差、重复性和回弹。
