# 三维目标位置控制与伸缩、弯曲协调的离线实现

核实日期为2026年10月30日。当前交付是独立开发副本中的纯Python三维位置模块、模拟入口和验证证据。没有连接机械臂、真实相机、串口或工作站，没有改PPT。

## 实现与接入边界

新的入口为 `CartesianController.move_position(PositionGoal)`。输入是同一参考系中的米制目标位置；被控制点为 `CameraPose.child_frame`。目标可以附带朝向范围约束，当前不优化朝向，也不接受任意六自由度位姿控制的解释。

两个弯曲作动坐标和一个伸缩作动坐标组成三维输入。显式3×2混合矩阵将两个弯曲坐标分配到三台电机，再加第四路伸缩形成4×3分配关系。统一3×3局部雅可比将这三个坐标映射到相机平移。

默认 `alternating` 策略针对同一个最终误差计算两个分块的阻尼最小二乘候选，按预测下降量选择弯曲或伸缩小步。`coordinated` 策略在模拟中同时计算三个方向并分配四路目标。两种策略都在每次运动稳定后获取新观测，最后用额外独立时间窗确认整体目标。没有把某个分块成功当作三维任务完成。

这是在既有包中新增的模块与离线入口。旧控制类、旧展开/收回、旧弯曲控制和ROS节点均保持逐字节不变。当前没有把新模块接入旧ROS服务或原生电机串口；缺少ROS/真实执行器适配时不能称为可直接上机版本。新模块拒绝没有明确 `simulation-only` 标识的I/O提供者，当前入口仅创建合成机构，不包含物理适配器。这是执行范围限制，不是对任意第三方Python对象的安全认证。

## 模型学习与运动约束

每步使用稳定电机反馈和运动后的新相机帧组成配对，基于实际作动变化更新3×3雅可比。低位移、噪声主导、方向不一致、异常时间配对和使矩阵退化的更新被拒绝。模型按同一参考会话保留，地图变化锁定失败；有限的方向覆盖不宣称完整标定。

四路作动行程、单步、累计行程、模型有效半径、条件数、任务时限和无进展次数分别受限。位姿时间倒退、未来或过期、失跟、地图变化、电机反馈无效/过期、运动越界、共同收放模式偏移均拒绝继续。取消与最终成功提交共用状态锁。故障后停止请求保留逐路模拟回执，重复请求不继续发运动命令；不确认的停止回执不会写成已经确认制动。

## 模拟模型与结果

模拟机构使用独立的非线性位置函数，包含弯曲—伸缩耦合项、二次项、传动系数偏差及独立随机相机噪声。控制器只通过时间、读观测、下发目标和停止接口工作，不读取真值函数。测试目标由模拟真值模型中可达的作动位置构造，真实作动值不交给控制器；这验证这些目标上的收敛，不构成真实工作空间证明。

默认模拟任务容差为0.5毫米，相机三维噪声界配置为0.06毫米，位姿年龄上限150毫秒。这些是新增模拟模块的显式参数，旧代码参数未改。不能将这些数值解释为实际D405测量精度或机械臂验收值。

最终22项测试方法通过，记录33个场景条目，其中14个预期成功，其余为故障或取消检查。连续三目标场景按一个条目保存，不把这些计数当作独立物理实验或可靠性概率。

| 模拟场景 | 修正步数 | 独立模拟真值最终误差/mm |
|---|---:|---:|
| fixed_jacobian_comparison | 13 | 0.348 |
| linear_alternating | 12 | 0.264 |
| nonlinear_alternating_0 | 12 | 0.205 |
| nonlinear_alternating_1 | 17 | 0.298 |
| nonlinear_alternating_2 | 17 | 0.343 |
| nonlinear_alternating_3 | 17 | 0.319 |
| nonlinear_coordinated | 7 | 0.200 |

四个非线性分时协调目标都需要两个弯曲方向和伸缩参与。相同目标下的分时、同步和固定雅可比对照仅反映本次合成模型，不能据单次步数宣称通用性能优势。模拟用时采用虚拟时钟，不代表真机速度或制动时延。

不可达目标、实际运动方向退化、假正常电机反馈、失跟、旧帧、串口以外的模拟电机反馈故障、取消、越限及超时场景均没有误报到位。这里未运行真实串口编解码或ROS中间件。

## 发现并修复的边界

模拟时钟最初因浮点累积产生极小的未来时间戳，现改为整数纳秒时钟。控制器的未来时间戳拒绝条件没有放宽。

`run02_boundary_checks`保留两项失败。固定帧数窗口在100Hz输入下无法累计足够稳定时间；现在同时按新帧数量和时间跨度判断。另一项复现最终复核后、成功提交前收到取消仍可能报告成功的问题；现在取消受理与成功提交在同一状态锁内仲裁。最终 `run03` 的22项全部通过。

从ROS接入副本复制后新增4个源模块/入口与测试文件，没有改写复制来的既有文件。对原 `01_Source/current`、`original_snapshot`、`original_archive` 和 `05_History` 的1189份受保护文件重新计算SHA-256，全部一致。来源及复制文件清单见开发副本 `SOURCE_PROVENANCE.json`，当前传统控制入口不被自动替换。

## 仍需真实设备确认

1. Mark调整后的24V供电能力，展开、保持、弯曲、收回以及组合动作时是否掉电或停机。
2. 四个物理电机通道、方向、零点、作动行程和允许形态；模拟使用的共同收放约束及4×3分配关系是否成立。
3. 同一机构状态下的初始3×3雅可比、三个运动方向的独立性，以及不同展开程度、负载、摩擦和回差对局部模型的影响。
4. 相机与任务参考点的关系、坐标标定、实际连续帧率、端到端时效、噪声与跟踪中断。离线150毫秒参数暂不作为现场保证。
5. 实际绳索张力、机械承重、允许速度和故障保持/制动方式。模拟停止确认不证明物理安全停止。
6. 在限定安全工作区内，用独立位置参照验证到位误差、重复性及稳定时间，再决定实机容差和模型有效范围。

ROS接入适配与消息级模拟验证仍可以离线继续做；它们不是必须等待设备才能进行的工作。当前交付范围是统一控制逻辑和独立机构模拟，尚未提供该适配。

## 运行

使用本机现有Python，无需安装或启动ROS。开发副本路径为 `01_Source/development/atarm_controller_cartesian_sim_20261030_v1`。

```powershell
python -B tools/run_cartesian_sim.py --target 0.3124208 0.03748 0.1949592 --strategy alternating --output <新的结果目录>
python -B tests/test_cartesian_offline.py <新的验证目录>
```

CLI只创建合成机构。结果包括目标、最终独立真值误差、逐步电机目标和模型更新。选择新的输出目录以保留已有演示结果。
