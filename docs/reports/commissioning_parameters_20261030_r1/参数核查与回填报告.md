# v4 参数核查与回填报告

2026-10-30 R1。本轮只读核对王师兄原始源码、固定 SDK 归档、历史真实 bag 的提取日志、既有配置和离线验证结果。本次没有连接工作站或实机，没有重跑 ROS/SLAM，没有修改控制代码或 PPT。

已在 v4 内新增[参数审阅版 R1](../../../config/commissioning/source_audit_20261030_r1/README.md)，原空模板和原版本保留。审阅版有两份执行模板，以及独立的历史参考与逐参数证据文件。

**本次确认的是资料、SDK 和软件行为的适用范围，没有新增当前实机已验证参数。** 历史日志能证明过去使用了哪些端口；代码默认值不能自动证明今天的安装、零位或安全限值。

## 1. 已补入执行模板的 15 个字段

| 字段 | 回填值 | 已验证到什么程度 |
|---|---|---|
| 两路 `ports.*.data_bits/parity/stop_bits/flow_control`，共 8 字段 | 8、N、1、none | 固定 SDK 默认声明与 v4 已实现、PTY 验证的受支持配置一致；当前 USB 适配器设置尚未现场读回 |
| 四路 `channels[*].gear_ratio`，共 4 字段 | 9.1 | 固定 SDK 的 A1 查询结果已由既有 codec 执行记录验证；原代码也明确选择 A1。仍需核对现场实际电机型号，不能把它解释为卷筒或机构传动的实测结果 |
| `ros.pose_topic` | `/atarm/camera/pose` | 已有工具包与节点的接口契约；不代表现场已有合格的实时定位发布器 |
| `ros.source_status_topic` | `/atarm/camera/source_status` | 同上，须与位姿具有相同捕获时间并带尺度、跟踪和地图会话 |
| `stop.policy` | `zero_effort_requires_external_support` | v4 已实现的策略；不等于已验证机械臂会保持不下垂，现场支撑与停止确认仍为 false |

此前已填写的原生库路径、SHA-256 和命名空间保留。控制器已有的 150 ms 视觉年龄、100 ms 电机接收年龄以及其他算法策略原样保留，并在证据中注明只经过离线/模拟验证。实机位置容差、实际噪声、速度、行程及初始 J 仍为空，没有用这些默认值替代实测。

两份执行模板仍为 `hardware_enabled=false`，六项现场确认均为 false。上述回填不会解除实机启动门槛。

## 3. 三处不能自行取值的分歧

| 项目 | 原节点/控制库 | 原 launch 或注释 | 本次处理 |
|---|---:|---:|---|
| 展开电机方向 | -1 | launch 为 +1 | 展开方向保留 null；由 Mark 确认当时入口/覆盖参数，再以受支撑的小幅动作核对 |
| 展开增益倍率 | 3.0 | launch 为 1.0 | 两种路径均保留；v4 显式协议增益继续为空 |
| 弯曲角上限 | 实现中的变量为 60° | 方法注释写 `[0,π/6]`，即 30° | 都不当作当前安全工作区，不写入动作约束 |

现有维护副本将展开方向和增益的默认值改成了 0，作用是“尚未设置”的哨兵，不能把它当成第三种实际安装方向或有效增益。

## 4. 旧增益已经换算，避免混淆单位

原公式为 `kp_protocol = output_kp / gear_ratio² / 26.07`，`kd_protocol = output_kd / gear_ratio² × 100`。

使用已核实的 SDK A1 常量 9.1，可计算以下**历史参考**。

| 原倍率 | 协议 Kp | 协议 Kd |
|---:|---:|---:|
| 1 | 0.006948122124 | 3.018959062915 |
| 3 | 0.020844366372 | 9.056877188745 |

这些数值由原公式计算得到，没有进行实机整定，不写入执行字段。v4 的 `kp/kd` 使用协议侧参数，不能直接填 15/2.5；先前 PTY 测试的 0.06/0.08 也不是旧机器的已知增益。

## 5. 其他已找到但不能冒充当前标定的资料

原几何模型保留边长 190.526 mm、鞍形段长度 123.236 mm、中性夹角 27.936°、固定长度 155.564 mm，以及三索 0°/120°/240°方向。这些是王师兄模型的常数，不是实测三维 J、基座外参或四索参考零点，已单独收入历史参考文件。

历史真实 RGB-D 数据支持 848×480、约 15 Hz、16UC1 深度以及约 0.001 m/整数单位的尺度，原配对容差为 2 ms。它们是有具体 bag 范围的记录。原 ORB 配置的零畸变内参用于派生去畸变图像，不应给当前 raw CameraInfo 使用；内部名义基线与深度到彩色外参也不能替代相机到臂基座/工具的外参。

已有同步核查在八份已知 ROS2 bag 中没有找到合适的主臂明显运动与同步 RGB-D 样本，因此不能从现有结果宣称已得到当前三维 J。历史单段位姿波动也不能直接填作真实相机噪声上界或到位精度。

明确排除了 PTY 用的 4,800,000 baud、末端舵机的 57,600 baud、合成 J/B、合成位置/零位/噪声与合成控制误差。它们没有进入主臂实机参数。

## 6. 如何使用与查证

使用 R1 目录内的 `site.template.json`、`session.template.json` 建立新的现场副本，按[剩余现场确认事项](剩余现场确认事项.md)继续填写。不要将历史参考 JSON 作为 site 配置；它缺少启动配置所需结构，也不会被启动器自动读取。

本轮没有将 R1 复制到工作站。若在工作站使用，先把这个 R1 目录复制过去；原 v4 启动说明中“复制模板”的来源改为 R1，其他 `check/run` 入口不变。`session_file` 保持与副本中的实际文件名一致。历史空模板继续保留。

`parameter_evidence.json` 保存 26 组参数判断、33 条来源锚点、文件 SHA-256、行号、摘录、是否写入执行模板和适用范围。来源包括原始快照、固定 SDK 原文、既有测试 JSON 与历史日志；没有执行原始 Python 控制库，没有导入它的 SDK，也没有访问设备。

离线检查确认审阅版仍拒绝实机启动、冲突/未知字段仍为空、历史参考不能直接启动，以及所有既有受保护文件哈希不变。该检查不替代现场参数或真实通信验证。
