# Mark 工作站上的机械臂实机测试流程

版本为 2026-10-30 v1，供到实验室后执行与记录。本次只依据本地源码、既有部署回执和录音整理编写，没有连接工作站、相机、电机或底盘，没有运行实机命令，也没有修改 PPT、控制代码和阈值。

先完成新供电与基本动作验收，再进行电机、视觉和局部运动学标定，最后验证伸缩与弯曲共同消除三维位置误差。首日若只完成供电与基础动作并带回可追溯数据，也构成独立有效的阶段成果，不为赶到三维闭环而跳过前置检查。

本轮目标是三维位置控制，末端姿态作为约束或记录量，不代表已经实现六自由度位姿控制。


### 3.2 可独立运行的三维 ROS 模拟演练

这一步可在正式接硬件前复习目标、回执与状态流程。命令据现有已验证容器配置整理，本轮只静态核对，未重跑。容器不映射设备、不接外网，退出后删除自身容器，不会操作实机。

```bash
docker run --rm -it --pull never --network none --read-only \
  --cap-drop ALL --security-opt no-new-privileges \
  --user "$(id -u):$(id -g)" --cpus 2 --memory 1g \
  --tmpfs /tmp:rw,size=128m \
  -e ROS_LOG_DIR=/tmp/ros-logs -e ROS_LOCALHOST_ONLY=1 \
  -e ROS_DOMAIN_ID=166 -e PYTHONDONTWRITEBYTECODE=1 -e PYTHONPATH=/project \
  --mount type=bind,src=/home/zcd/codex-runs/atarm-cartesian-ros-sim-20261030-01a1831d/project,dst=/project,readonly \
  ros@sha256:8eed0a4669bbf43ee331878a4c39bd8ebddea8e3312a58b4fae8edb14526b617 bash
```

在同一容器终端内启动节点和状态订阅，保留进程号。

```bash
source /opt/ros/jazzy/setup.bash
python3 -B -m atarm_controller.cartesian_sim_node > /tmp/cartesian-node.log 2>&1 &
cart_node_pid=$!
ros2 topic echo /atarm/cartesian_sim/state std_msgs/msg/String > /tmp/cartesian-state.log 2>&1 &
cart_echo_pid=$!
ros2 service list -t
```

确认模拟节点服务已发现，再发一条已有验证目标；这里只是演练，坐标不可抄到实机。

```bash
ros2 topic pub --once /atarm/cartesian_sim/target std_msgs/msg/String \
  '{data: "{\"request_id\":\"lab_sim_001\",\"position_m\":[0.3124208,0.03748,0.1949592],\"parent_frame\":\"sim_base\",\"child_frame\":\"camera_optical\",\"map_epoch\":\"sim_map_0\"}"}'
tail -n 10 /tmp/cartesian-state.log
```

若要练习取消，另发新 ID，在状态为 RUNNING 时调用。

```bash
ros2 service call /atarm/cartesian_sim/cancel std_srvs/srv/Trigger '{}'
```

`accepted=true` 只表示受理。完整运动必须看到 `job.state=SUCCEEDED`、`job.success=true`、`job.complete=true`。取消或故障后需显式模拟重置，重置会更新 `map_epoch`，旧目标应拒绝；模拟重置不会建立任何实机零位。

```bash
ros2 service call /atarm/cartesian_sim/reset std_srvs/srv/Trigger '{}'
```

只在任务结束后使用该模拟重置。下一条目标从状态读取新的地图会话并采用新的 ID，不能继续使用上例中的 `sim_map_0`。

结束时只停止自己启动的两个进程，随后退出容器。不要使用全局 `pkill`。

```bash
kill -INT "$cart_node_pid"
wait "$cart_node_pid"
kill -TERM "$cart_echo_pid"
wait "$cart_echo_pid"
exit
```

### 3.3 相机和记录程序

独立相机驱动应在已有可用的采集机/驱动容器启动。先确认该主机、ROS 发行版和相机专用 launch；历史提过的双相机 launch 源码未交付，不能把其名字当已验证启动命令，也不要为找相机话题启动整台机器人。

在**已 source 的相机 ROS 环境**中只读检查。

```bash
printenv ROS_DISTRO
printenv RMW_IMPLEMENTATION
printenv ROS_DOMAIN_ID
ros2 pkg prefix realsense2_camera
ros2 topic list -t
ros2 topic info -v /camera1/camera1/color/image_raw
ros2 topic info -v /atarm/camera/pose
```

话题前缀以现场实际发现为准。跨主机确认 DDS 可达、QoS 和时钟；同一 ROS_DOMAIN_ID 并不能证明跨发行版或跨网络链路兼容。模拟用 `--network none` 容器只供上节演练，不能直接拿来接收另一台采集机的图像。现场采集/控制容器的网络、消息包和设备映射需单独确定，不修改上述冻结模拟镜像来凑实机环境。

相机工具包已部署在工作站，但运行它的环境仍须有驱动自定义消息并能发现相机话题。若采集在另一台机器，应明确部署同版工具；不假设工作站路径在采集机也存在。

在满足这些条件的工作站 ROS 环境中，先做 10 秒 camera1 检查。每次采用新的会话目录，下面通过新建目录保证不覆盖旧结果。

```bash
field_run=/home/zcd/agri-arm-tests/$(date -u +%Y%m%dT%H%M%SZ)_camera_check
mkdir -p /home/zcd/agri-arm-tests
mkdir "$field_run"
python3 /home/zcd/agri-camera-fieldkit/current/capture.py plan \
  --config /home/zcd/agri-camera-fieldkit/current/config_camera1.json \
  --out "$field_run/plan.json"
python3 /home/zcd/agri-camera-fieldkit/current/capture.py record \
  --plan "$field_run/plan.json" --out "$field_run/pilot" \
  --duration 10 --label pilot_c1
python3 /home/zcd/agri-camera-fieldkit/current/analyze.py \
  --bag "$field_run/pilot/bag" --plan "$field_run/pilot/plan.json" \
  --receipts "$field_run/pilot/receipts.jsonl" --session "$field_run/pilot/session.json" \
  --out "$field_run/analysis"
```

先检查 plan 中 `ready=true`、必需 CameraInfo/深度到彩色外参到齐、录制完成、必录话题非空、解析与写盘日志无错，再延长到 180 秒。上述命令未加 `--clock-verified`；只有实测确认时钟依据后才添加，不能靠该开关建立同步。

有合格独立定位节点后，用 `capture.py plan --with-pose` 将位姿与源状态纳入新计划。静态波动分析额外加 `analyze.py --static`，只用于确实固定的机构与场景。工具包只录其计划中的相机/位姿话题；电机、电源、控制目标和停止事件须另行显式列出并同步保存，不能假设相机 bag 自动包含它们。详细步骤沿用原[相机现场操作清单](../../EXTERNAL_REFERENCES.md)。

### 3.4 实机控制启动必须满足的条件

以下工作可以在实机闭环前离线补齐，本次流程整理不修改代码。

1. 在新的实机开发副本中接入经校验的串口工厂，明确两路设备白名单、四电机映射、逐路新鲜反馈和唯一 I/O 线程。旧节点 CLI 当前没有这项注入；直接 `is_dry_run=false` 会被拒绝。
2. 为三维控制建立独立真实执行器接口和 ROS 任务所有权。保留模拟专用版本，不伪装 `simulation-only`。启动时不自动运动，初始状态保持未标定/未就绪。
3. 将真实定位输出接入位姿桥，再接入三维 Observation；已有 `RosPoseBridge` 还没有连到 v2 三维控制器。定位必须提供与图像对应的时间戳、米制尺度、跟踪状态、坐标系和地图会话。
4. 配置只允许经过现场签认的电机方向、参考长度、行程、速度、步长与电流/张力相关约束。当前旧包把 `deploy_motor.direction=0`、`deploy_motor_torque_gain_scale=0` 作为未设置哨兵值；不得为通过启动随便填正负号或增益。
5. 用消息级模拟与伪串口验证真实接入的停止、掉反馈、地图切换、重启和退出，保证取消/故障后不会自动继续或自动归零。

全部就绪后按这个顺序启动实机链路：先独立电源/机械检查与记录，再启动相机驱动和定位，再核对有效源状态与记录器，然后启动执行器接入和空闲控制节点，确认没有运动且标定引用一致，最后人工允许一条小幅动作。软件构造电机对象可能发送模式初始化报文，`auto_deploy_on_start=false` 不能解释为“没有任何设备 I/O”。

当前没有合格的统一实机命令，所以本节不提供一个会误驱硬件的占位 launch。到场基本动作可采用 Mark 已确认的手动入口；若他也没有可验证入口，先停留在电源、相机采集和参数确认阶段，将上述接入补齐后再动。

## 4. 先验新供电和基本动作

通过第 2 节检查后，使用现场已确认的低速小幅控制方式。先不连接视觉闭环，不用 5 cm 默认展开量做第一次动作。

| 次序 | 动作 | 必须记录与观察 |
|---|---|---|
| P0 | 通电但不主动运动，观察稳定保持 | 电池/转换器/电机端电压，电流、错误码、异常声响、接头与散热状态 |
| P1 | 一次小幅展开，停止并保持，再小幅收回 | 编码器、实际长度、端部位移、峰值电流/最低电压、是否掉电、滑索或卡滞 |
| P2 | 小幅两个独立方向弯曲，各返回参考形态 | 三路弯曲索的响应与未命令通道运动、弯曲时是否拉动展开索 |
| P3 | 小幅展开后弯曲，再归中收回 | 组合动作时供电是否仍稳定，停止后是否回弹/下垂，张力是否可维持 |
| P4 | 在已确认的范围内重复同一组动作 | 建议先连续 3 次作工程筛查；逐次保存，记录是否复位、温升或误差累积，不解释为可靠性统计结论 |

首次幅度、速度、保持时间、次数以及电气停止阈值都先填入记录表，再由现场负责人确认。幅度须高于测量分辨率、低于已确认可用余量。本文不把模拟参数当真机允许值。

通过依据是所有被接受动作都能正常执行、停止与保持，供电不掉出器件允许范围，不复位、不触发故障，索与机构无异常；有一项失败就保留日志，先处理供电/机械/映射问题。电压下降、电流过大时不通过放宽保护或提高增益继续试。

## 5. 如何标定

### 5.1 电机、索长和机械参考

逐通道标定总线、ID、方向、编码器增量和实际索长增量。代码中的正索长表示收紧，不自动等于末端向前或向上；用实物观察确定符号。代码里的卷筒半径 26 mm 是既有模型值，需要核实有效半径及绕索层数是否改变换算。

用物理标记或独立测量建立可复现起始形态，记录四路索长 `q_ref`、机构长度、相机安装和载荷。启动编码器零点不证明机械臂已收回；现有 `confirm_retracted_reference` 要求独立机械确认，且其作用不等同四路索统一重新归零。中途重启、拆索或滑索后重新确认。

现有主臂没有在本轮核实张力传感器。电机反馈力矩也不能不经机构模型和摩擦校验就当成索张力；没有独立张力测量时，至少记录索路状态和明确受限的试验范围，不把“没有松索”写成定量张力验收。

### 5.2 相机尺度、坐标和控制点

先固定底盘、末端舵机与载荷。核对相机序列号、安装位、RGB/深度内参、深度尺度和时间戳。D405 的深度到彩色外参不是相机到臂端或地图到基座的外参；camera1/camera2 的编号也不能替代安装身份。

用独立标尺/标定板给出已知位移，验证定位输出的米制尺度、三个轴方向及位姿方向约定，不能只看轨迹形状。若仅有视觉地图坐标但没有固定基座锚定，可以先测试同一地图会话内的局部目标，不能称为基座坐标下的指定位置控制。

若要控制工具尖端，在明确变换方向后计算：

`T_base_tcp = T_base_map · T_map_camera · T_camera_tcp`

这里 `T_a_b` 把 b 系坐标变换到 a 系。相机光心为控制点时省略最后一项。相机姿态变化会通过工具偏置改变尖端位置，不能只给相机位置加一个固定世界向量。用未参与外参求解的检查点验证该变换，记录重投影/空间残差及独立参照的不确定度。

目标、反馈必须描述同一控制点、同一父坐标系和同一 `map_epoch`。地图重建或定位重置后停止，重建基座关系与目标；不把旧目标换个 epoch 标签直接重发。

### 5.3 先测视觉是否足以闭环

机构与场景保持静止，先保存约 180 秒数据，测位姿各轴波动、漂移、有效帧数、最长连续有效段、失跟和地图切换。再在小幅运动下测源捕获到控制使用的完整年龄，以及停止后到稳定窗口的时间。

三维版本已有 `max_pose_age_s=0.150`、`max_motor_age_s=0.100`，二者是不同反馈的代码门槛，不是本次现场验收结果。要检查上一帧在下一帧到达前的最大年龄，不能仅用平均 15 Hz 或图像间隔证明 150 ms 连续满足。多主机时钟偏差尚未量化时，延迟记为未确认。

`position_tolerance_m=0.0005` 与相机噪声等默认值来自模拟，不能作为已证明的 0.5 mm 真机能力。现场先填写任务允许误差，再判断视觉不确定度、稳定窗口、外参误差和独立参照是否足够支持它；不足时先报告实际可测范围，后续另建经确认的实机配置，不修改历史阈值凑通过。

### 5.4 建立协调伸缩和弯曲的初始雅可比

在一个供电稳定、索保持有效张力、视觉稳定且离行程边界有余量的参考形态上进行。记三维控制坐标为 `u=[b1,b2,e]`，其中前两维是独立弯曲组合，第三维是展开索控制量，均按定义采用长度单位；四电机反馈为 `q=[q1,q2,q3,qe]`。

当前模拟使用 `Δq=BΔu`，B 为 4×3 矩阵，前三行的第三列为 0，第四行为 `[0,0,1]`，弯曲两列的三索合量为 0。这个结构意味着三维协调由雅可比解释耦合，但不主动调整三弯曲索共同收紧量。实物若展开时必须同步收放三索才能维持张力，需要先调整执行器映射/张力策略并离线验证；不能强行把实物反馈塞进模拟的控制子空间。

实测 B 的列方向与幅度必须由电机/索路映射支持。不要把电机原始转角、弯曲角度、米制索长混在同一个雅可比里。

| 步骤 | 操作与数据 |
|---|---|
| J0 | 记录参考形态的一段新鲜稳定位置 `p0` 和四路实际索长 `q0` |
| J1 | 只对 b1 施加已确认小幅正/负扰动，各次都经过独立确认的参考形态，稳定后采位置和实测索长 |
| J2 | 对 b2 做同样扰动 |
| J3 | 对 e 做同样扰动；观察是否改变弯曲、张力或产生三索共同运动 |
| J4 | 每维建议至少重复 3 组，保存完整进出路径与返回残差，用来观察噪声、回差和漂移 |
| J5 | 用不同于拟合数据的组合小扰动检验预测，再决定可用局部范围 |

每次扰动须等待电机反馈稳定、图像源时间晚于动作稳定时刻，且有多个新源帧构成稳定窗口；不能在发完命令后立刻取一帧配对。物理不允许负向扰动时用单边数据并注明，不强求对称动作。

理想对称小扰动下第 i 列可写成 `J[:,i]≈(p_plus−p_minus)/(2h_i)`。实际拟合优先使用稳定前后**实测**的 `Δu` 与 `Δp`，多个样本做最小二乘；编码器未到位时不能以命令幅度代替分母。扰动需能分辨于视觉噪声与回差，同时处于局部近似有效范围。

检查三列能否产生三个独立方向，用奇异值/条件数判断退化，并报告采用的坐标单位与归一化。模拟的秩和条件数门槛尚未经实机标定，不作为本次自动通过线。若三方向不独立，或预测残差/往返差与目标误差同量级，先改变参考形态、测量或模型，不能宣称局部三维可控。

开始先冻结这个实测 J 做小目标测试；预测和实际方向一致后，再开启有界在线更新。只用同一会话下、真实执行且稳定的位移对更新。失跟、松索、限幅未执行完、地图变化和明显振荡期间不学习。Mark 所说的逆运动学在这条路线中由局部雅可比的阻尼数值逆承担，实测 J 是必要起点，无需先求一套全局解析逆运动学。

## 6. 怎样验证协调到达三维目标

### 6.1 统一成功标准

先在记录表填好目标容差、保持窗口、时间/路程预算、视觉得分条件和停止线；缺少这些定义时只记探索性结果。由独立标尺、标定板、外部测量装置或其他已标定参照确定目标与最终位置，精度应足以支持拟验收容差。若最终误差只来自同一个 SLAM 输出，只能验收反馈坐标内的一致性，不能据此确认绝对到位精度。

单次成功必须同时具备以下证据。

- 目标受理 ID 与最终状态一致，最终为成功完成，取消/故障/超时均计为未完成。
- 同一坐标与地图会话内，多帧新鲜稳定观测的误差在预定容差内，持续预定窗口；不能靠瞬间穿越目标。
- 四电机实际反馈合法、稳定、在限制内，未靠“已发送命令值”等于目标判定完成。
- 独立测量得到最终三维误差和参照不确定度，并记录停止后的回弹或下垂。
- 动作中电压、电流、机构状态和视觉时效均符合本次预定条件。

### 6.2 分级测试顺序

| 级别 | 目标与模式 | 解决的问题 | 通过后再进行 |
|---|---|---|---|
| V0 | 参考形态保持，不发运动目标 | 起点、视觉、供电与测量是否稳定 | V1 |
| V1 | 三个独立控制方向的小扰动，冻结 J | 电机方向、映射与局部预测是否一致 | V2 |
| V2 | 参考点附近的单轴位置目标，先用 alternating | 单个三维误差目标能否收敛；不要求动作只用一个执行器 | V3 |
| V3 | 同时含轴向和侧向分量的目标，用 alternating | 同一最终三维目标下交替伸缩/弯曲是否减少总误差 | V4 |
| V4 | 对 V3 同一批目标和初始形态采用 coordinated | 同时求解两弯曲量与展开量是否稳定，有无电流/振荡代价 | V5 |
| V5 | 在有效局部范围内换至少两个展开水平、不同侧向方向，再测试返回与重复 | 耦合、形态依赖和回差能否被识别，是否需要分形态标定或模型更新 | 扩范围另立试验 |

alternating 每步从弯曲组或展开组中选择有利于降低同一三维误差的动作；它已经是协调控制，不是固定先展开再弯曲。coordinated 同步求三维增量，可能增加同时负载，应在组合动作供电验证后再尝试。

V3 目标应选为纯弯曲或纯伸缩在当前限制下难以单独满足的混合位移。结合实测 J 比较各执行器子集对目标的预测残差，并在日志中确认两弯曲坐标与展开量有实际变化。仅看末端走了斜线，不能证明协调算法起作用。

每个核心目标建议先做 3 次工程重复，记录所有成功、失败、取消与未尝试项及原因。比较两模式时保持初始形态、目标、载荷、速度/电源限制、视觉配置和容差相同；J 和学习状态从同一基线开始。若开在线更新，应保存各自更新轨迹，避免后测方法无意继承更多标定信息。少量重复只用于现场筛查，不宣称普适成功率。

### 6.3 每个目标具体怎么做

1. 回到经机械与视觉确认的参考形态，记录本次起点和模型版本。不是把编码器值强行清零。
2. 输入明确父坐标系、控制点、地图会话和唯一 ID 的三维目标，确认在已校验的局部可达与无干涉范围内。
3. 确认记录器已收齐图像/位姿、源状态、四路电机、电源和控制状态后，才受理一条目标。
4. 看总三维误差、每步伸缩/弯曲选择、实测 Δq 和模型预测是否一致，同时观察电气与机构状态。目标受理期间不追加第二条目标抢占执行器。
5. 达到稳定窗口后保存独立参照测量；未完成则记录最后误差、故障/取消原因及停止证据，禁止改写成成功。
6. 按已验证方式返回或支撑停止，保存本次目录；下一次采用新 ID 和新记录行。

最终至少画出总位置误差随时间、三个轴误差、两弯曲控制量和展开量、四路实测索长，以及电压/电流变化；标出取消、掉反馈或模型更新时刻。比较实际到位误差、完成用时、总索长行程、峰值电流/最低电压和失败原因，不能只展示一条最好看的轨迹。

## 7. 异常与结束

出现索路异常、未命令运动、明显卡滞/振荡、电气越限、设备重启、位姿失跟/冻结/跳变或地图切换时，按已验证停止方式结束动作。先固定机构，再处理掉电或卸力；保留停止命令、通信回执和实物停止/保持的独立观测。软件取消时间不等于真实停止时间。

危险故障不在实机上靠拔线、堵转或故意制造欠压来重现，优先通过已有模拟注入验证软件分支。现场只在受支撑的小动作中测试已确认的取消与停止。故障后重新核对供电、索路、零位和视觉会话，人工复核后新建任务，不自动续跑。

结束前先确认机构处于已验证的支撑/保持形态，再关闭本次控制进程与电源，停止记录并检查文件完整性。保存源码哈希、配置、版本、完整 bag、控制/电源/独立测量日志、错误和中断记录。生成原始数据哈希，复制后核对；原数据不覆盖、不补帧、不修改时间戳，不自动上传。
